# برّاني — Flutter

Native Flutter rewrite of the game. Runs alongside the original React/Capacitor
app at the repo root, which stays the shipped version until this reaches parity.

## Content is generated, not authored here

`lib/content/packs.dart` is **generated**. The TypeScript packs at
`src/content/packs/*.ts` remain the single source of truth so the two apps can
never drift, and so the existing validator keeps guarding every pair.

```bash
npm run export:dart   # from the repo root
```

Editing `packs.dart` by hand will be overwritten.

## Commands

```bash
flutter test        # engine, store, and reveal-leak tests
flutter analyze
flutter run                      # onto a connected device
flutter build apk --release      # build/app/outputs/flutter-apk/app-release.apk
```

## Architecture

Mirrors the React app deliberately, so behaviour can be compared directly:

| Layer | Files | Notes |
|---|---|---|
| Content | `lib/content/` | Generated data + `Pack`/`WordPair` types |
| Engine | `lib/engine/` | Pure Dart. No Flutter imports, no I/O, no globals. Randomness is an injected `Rng`. |
| State | `lib/state/` | Immutable `Session`, sealed `Phase`, and `SessionStore` as the only place transitions happen |
| UI | `lib/ui/` | One widget per phase; all of them dumb |

### The RNG is deliberately bit-compatible with TypeScript

`lib/engine/rng.dart` reimplements mulberry32 including a hand-written 32-bit
multiply, because Dart ints are 64-bit and would not wrap the way `Math.imul`
does. `test/engine/rng_test.dart` pins the output against values generated by
the TS implementation — the same seed deals the same round in both apps. If
those tests ever fail, the port has silently diverged.

### HoldToReveal

Its contract is not "hide the word" — the word is **never built into the widget
tree** until a deliberate hold completes, and leaving the foreground clears it.
`test/hold_to_reveal_test.dart` is the guard.
